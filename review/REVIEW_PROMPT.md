## Background

This benchmark translates a Rust algorithm (`src/lib.rs`) into Lean (`{{CRATE_LEAN}}`, auto-generated by the charon→aeneas pipeline), optionally translates its Rust tests (`tests/test.rs`) into `Test_test.lean` (auto-generated, ends in `#eval` checks), and pairs them with a hand-written `Spec.lean` that states a correctness theorem. `Spec.lean` theorems are proved with `by sorry`, so they compile regardless of whether they are TRUE. Your review must decide whether each statement is actually true and complete.

## What to check (in this order)

### 1. Provability / truth of each theorem
For every `theorem ... := by sorry` in `Spec.lean`:
- Restate in one line what it claims.
- Judge whether it is actually true of the implementation: would a real Lean proof go through, or is the statement too strong / vacuous / false?
- Watch for over-claiming: does the conclusion actually follow from what the code computes, or does the spec assert a property the code does not guarantee?

### 2. Missing preconditions / conditions
- Compare the theorem hypotheses with what the Rust implementation actually requires.
- Does the Rust `assert!` / `massert` enforce a condition the spec omits (e.g. "matrix is invertible", "n ≥ 1")?
- Does the spec hold only on a restricted input domain that is not stated as a hypothesis?
- Does the spec under-constrain (e.g. forget that two operands must have the same size before claiming equality)?

### 3. Counterexamples (actively hunt for them)
Actively try to break the spec — do not just assert it looks fine:
- Add a temporary Rust test in `{{DIR}}/tests/` (or a scratch `{{DIR}}/src/bin/`), run `cd {{DIR}} && cargo test`, and DELETE it afterward.
- Or write a scratch Lean file `/tmp/review_{{NAME}}.lean` that imports `{{CRATE_MODULE}}` and `#eval`s a concrete call that should violate the spec, then run `cd lean_mode && lake env lean /tmp/review_{{NAME}}.lean`.
- For every candidate counterexample record: the concrete input, what the implementation actually returns, what the spec predicts, and how they disagree.
